# 비즈니스 지표 추출을 위한 DB설계 / SQL 분석 프로젝트
> OZO (Overstock to ZerO)
> 
> 국내 과재고 의류를 해외 바이어에게 중개하는 B2B 플랫폼 데이터베이스 설계 프로젝트  


---

## 프로젝트 개요

국내 패션업계의 악성 재고 문제와 해외 한류 의류 수요를 연결하는 B2B 중개 플랫폼의 DB를 설계했습니다.  
상품 등록부터 주문·결제·배송·정산까지 전 과정을 하나의 DB로 관리할 수 있도록 25개 테이블을 팀원 2명과 함께 설계했습니다.

---

## 기술 스택

- **DBMS:** Oracle
- **언어:** SQL

---

## 핵심 설계 의사결정

### 1. 결제 방식 분리 — LC 테이블 / ACCOUNT 테이블

B2B 해외 거래에서는 신용장(LC)과 계좌이체(TT) 두 가지 결제 방식이 공존합니다.  
두 방식이 필요로 하는 정보가 완전히 달라서 하나의 테이블로 관리하면 한쪽 컬럼이 항상 NULL이 되는 구조였습니다.  
결제 방식별로 테이블을 분리해 데이터 무결성을 유지했습니다.

### 2. 주소 체계 3단계 분리 — 대분류(시) / 중분류(구) / 소분류(동)

판매자 주소를 단일 컬럼으로 관리하면 지역별 검색·집계가 불가능합니다.  
시·구·동 3단계 계층 구조로 분리해 지역 기반 조회가 가능하도록 설계했습니다.

### 3. 상품 분류 계층화 — 대분류 / 중분류 / 소분류

의류 상품을 단일 테이블에 저장하면 카테고리 기반 분석이 어렵습니다.  
대·중·소 3단계 계층 구조로 분리해 "여성 > 아우터 > 자켓"처럼 특정 카테고리의 매출·재고를 독립적으로 조회할 수 있도록 설계했습니다.

### 4. 정산 VIEW 도입

정산금액은 배송 상태와 연동되어 유동적으로 변합니다.  
정산 공식(총결제금액 × 판매자비율 - 수수료 - 배송비)을 매번 쿼리에 반복 작성하는 대신 VIEW로 중앙화해,  
배송 상태 변경이 정산 결과에 자동으로 반영되도록 했습니다.
